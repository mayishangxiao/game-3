## 三、480×270 真机比例截图（规格表第十节）

`qa/mock_480x270.png` 是实际分辨率，`qa/mock_960x540.png` 是它等比 2× 放大便于查看，`qa/ratio_check.png` 是 16×16 瓦片 / 32×40 角色 / 96×48 Boss 的同尺度对照。

这一轮截图查出 3 个只在真机比例下才暴露的问题，已修：

1. **过渡边铺满整行** → 沙→石过渡瓦片横贯画面，读成一道横穿海滩的砖墙。现在只在炮台占位列（第 2-8 列）出现。
2. **木栈桥误用系缆桩格** → 桥面读成一堆木箱。甲板只用 0-2 号木纹格，第 4 格（沙地系缆桩）单独摆在桥头外侧。
3. **Boss 黑烟**（两轮）：真机下原来的逐像素抖动读成整齐棋盘块 → 改成实心烟团；改完在 8× 预览上又读成"一串分离的圆珠" → 再改成两遍法（先整片铺实心，再统一取左上外缘 1px `greyPlum` 提亮），现在是一条连续烟柱 + 与全作一致的左上受光。

## 五、需要甲方拍板的两件事

**1）引擎角色尺寸还是 24×32，规格表要求 32×40。**
`game/src/core/constants.ts` 现在是 `CHAR_W = 24 / CHAR_H = 32`，且 `CharacterRig`、`MapRenderer`、`Enemy` 仍是程序画的矢量占位，`public/art/` 是空目录、`config.json → ui.portraits` 是 `{}`。也就是说这批图**还没有接进游戏**。两条路：

- A：改 `constants.ts` 常量为 32×40 + 同步 `core/` 相关测试（`pnpm test` 会跑到），这是正解，但要动代码；
- B：素材按 32×40 画、进引擎时缩放显示 —— 会破坏像素对齐，不建议。

本轮按规格表出图（32×40），没有擅自改引擎。定了走 A 的话我可以顺手把接入做掉。

**2）清军号衣颜色：规格表 6.2 要墨绿/军绿，但先前口头要求过"清军衣服不要绿色"。**
本轮以规格表为准出了绿色系（绿营 / 把总 / 关天培）。如果仍按早先的意思走蓝色系，脚本改一处配色映射即可重出，代价约 5 分钟，不需要重画。

另外可选微调：石板炮台在地面上偏醒目（`plumLight` 底 + `plumMid` 砖缝），要不要整体压暗一档改成更"石"的观感，等真机截图反馈再定，不擅自改。

## 六、源工程文件说明

规格表第七节要求随附 .ase / .psd 源文件。本轮没有 Aseprite / Photoshop，改用**像素矩阵脚本**作为等价源：

- `_tools/gen_spec.py`：24 色调色板、8 色预算守卫、32×40 画布与行分区、姿势系统（idle/walk/attack/hurt/death）、7 个单位的配色配置、帧集与 512 图集输出。
- `_tools/gen_spec_assets.py`：Boss 96×48 六帧、6 组瓦片 + 3×3 平铺证明、鸦片箱 20×20、两张立绘。
- `_tools/check_spec.py`：第八节十条验收清单的脚本判定，输出 `qa/acceptance_report.txt`。
- `_tools/mock_scene.py`：480×270 真机比例场景截图。
- `_tools/patch_*.py`：本轮修订的历史补丁（保留以便复现改动来源）。

改色、改帧、改变体都只需改脚本里的配置再跑一遍，102 张图与验收报告会自动重出——比手工 .ase 更容易保证"全作同一套规则"。需要 Aseprite 可编辑文件的话，可以反过来把这些帧导出成逐帧 PNG 序列再在 Aseprite 里拼，但那一步应由做动画的人确认帧序习惯后再做。
