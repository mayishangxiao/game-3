## 9.5 史实校对流程

经过校对的内容才是"党史游戏"，没经过校对的内容只是"同人"。这个流程必须执行。

### 9.5.1 校对层级

| 层级 | 负责 | 工具 | 产出 |
| --- | --- | --- | --- |
| L0 · 开发者自校 | 开发者本人 | `five_element_check` 逐卡打勾 | 五要素自查表 |
| L1 · AI 互校 | 同样的 DeepSeek 模型，换用校对提示词 | JSON diff | 可疑条目报告 |
| L2 · 同伴交叉校对 | 另一名了解党史的同学 | JSON + 表格 | 逐卡校对签名 |
| L3 · 思政课老师审阅 | 思政课老师（自愿参与） | 可玩版本 | 最终意见 |

**第一期交付要求**：全部事件卡与知识卡至少通过 L1 + L2。

### 9.5.2 五要素自检脚本（`lint_history.js`）

### 9.6.3 AI 使用纪律

1. **AI 产出的内容绝不直接进数据文件**。先用脚本写入 `_ai_draft/` 目录，人工校对后搬到正式路径。
2. **对话生成**：每幕一次批量请求，Prompt 包含本幕全部事件卡的五要素 + 原型描述 + 字数约束，确保上下文连贯。
3. **校对**：用独立的校对提示词，只传 ID + 当前内容（不传 Prompt 模板），避免模型"自我确认"。
4. **预算耗尽预案**：JSON 结构已在本章定义，全部字段都有人工填写的备选方案——**可以不用 AI，只是更慢。**
