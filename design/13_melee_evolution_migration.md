# 近战强化「攻击向」设计迁移说明（v1.8）

> 独立交付物，不进设计书正文（`build_docx.py` 只拼 `00`–`07`）。
> 本文只回答三件事：老游戏里这套机制长什么样、哪些迁到当前项目、迁过来之后和现有系统怎么共存。

## 1. 老游戏里有什么

工作区里有两个旧版本，都实现了「近战局内进化」，且都是**攻击向**的：

| | `old game/history_game`（更老，机制最完整） | `game2`（后一版，收敛为数值卡） |
| --- | --- | --- |
| 数据表 | `scripts/evolution_data.gd`：`EVS` 9 张 | `data/evolution_data.gd`：`CARDS` 8 张 |
| 触发 | 击杀攒经验 → 升级排队三选一；每过一小关再额外给一次；`_process_evolution_queue` 重入保护 | 击杀升级 → `draw_three` 三选一 |
| 卡池 | 刃锋延展 / 横扫千军 / 背袭之刃 / 回旋斩 / 剑气纵横 / 疾风连斩 / 破军之力 / 震荡强击 / 嗜血战意 | 刃锋延展 / 破军之力 / 疾风连斩 / 嗜血战意 / 震荡强击 / 虎威之躯 / 疾行 / 横扫千军 |
| 叠加上限 | `unique`（唯一，只能选一次）或 `max`（可叠 3–5 次）；`eligible()` 把满级/已取唯一的踢出池 | 每张 `max_stack` 2–4；`draw_three` 过滤已满层 |
| 有效期 | **整条大关累积、进关重置**；卡片上明写「本关有效，进关重置」 | 同一场战斗内累积 |
| 界面 | `evolution_pick.gd`：暂停 → 三张卡，卡顶**彩色色条**、`unique` 显示「唯一 · 不可再选」、可叠显示「可强化 ×N」 | `evolution_pick.gd`：三选一，不暂停战斗 |
| 选后反馈 | `spawn_floating_text` 在玩家头顶飘「进化：刃锋延展」 | 打印日志 + 玩家 `on_evolution` |
| 战斗表现 | `battle_player.gd`：扇形阈值按点积判定、左右交替扫击弧光、后方追加斩击、360° 全周斩、`sword_wave.gd` 青色三层辉光穿透剑气、命中火花、硬直、吸血飘字 | 只改玩家标量（范围 / 伤害 / 间隔 / 吸血 / 击退 / 扇形），表现层较薄 |

`old game/history_game` 里特别值得迁的是**组合技**：`背袭 + 横扫` 会变成近似全向命中，`回旋 + 剑气` 变成八方剑气环，`背袭 + 剑气` 变成前后双向剑气。它让「选卡」从纯数值变成看得见的招式变化。

另有 `scripts/battle_talents.gd` 的「知识锦囊」（士气 +45%、近战与炮击伤害 +15%）属于跨局被动，不在这次迁移范围。

## 2. 当前项目已有的底座（v1.7）

`game 3` 已有一套**波次强化**：每清一波弹三选一，弓（齐射/火线/穿透）与近战（横扫/火线/破甲）共用同一组 id / 满级 / 6 次上限；`UpgradeBook` 按武器实例隔离状态；只在本关有效、换关清空。触发方式与老游戏的「击杀升级」不同，但**三选一、叠加上限、候选池过滤、本关累积、进关重置、选后即时生效**这些规则是同构的。

所以迁移不另起一套升级系统（那会破坏波次流程和存档），而是把老游戏的**攻击向卡池与表现**并进现有底座。

## 3. 迁移映射

| 老游戏条目 | 当前项目对应 | 处理方式 |
| --- | --- | --- |
| 横扫千军（扇形加宽） | `volley` → 横扫 | 已有，保留 |
| 疾风连斩（攻速） | `haste` → 火线 | 已有，保留 |
| 破军之力（伤害） | `pierce` → 破甲 | 已有，保留 |
| 刃锋延展（攻击距离） | `reach` 刃锋延展 | 新增，`reach` 倍率乘到判定与刀光半径 |
| 背袭之刃（后方追加斩击） | `behind` 背袭之刃 | 新增，后方扇形判定 + 反向刀光 |
| 回旋斩（每 3 刀一次 360°） | `spin` 回旋斩 | 新增，全周判定 + 全周弧光 |
| 剑气纵横（穿透剑气） | `wave` 剑气纵横 | 新增，青色穿透投射物；与回旋/背袭组合成八方、四向、前后双向 |
| 震荡强击（击退 + 硬直） | `knock` 震荡强击 | 新增，额外击退 + `Enemy.stun()` |
| 嗜血战意（命中回血） | `leech` 嗜血战意 | 新增，每次命中回血并飘 `+N` |
| 卡顶色条 / 唯一标签 / 可叠次数 | 卡片色条 + 卡面文案 | 新增 `UpgradeDef.color`，卡面按条目配色 |
| 「进化：X」头顶飘字 | 选卡后飘字 | 新增，沿用 toast 之外的即时视觉反馈 |
| 组合技（背袭+横扫 / 回旋+剑气 / 背袭+剑气） | 纯函数 `swordWaveOffsets()` + 近战命中弧 | 新增，效果与刀光同步 |

**保持一致的部分**：弓仍是原来 3 张卡、6 次上限、数值与文案逐字不变；近战仍是**同一套波次触发、同一本 `UpgradeBook` 按武器实例隔离、同一个 6 次上限、同一个本关内清零**；火枪/机枪等其它远程依旧不参与、不弹卡。0 级时新增效果全部为单位元，不改动近战基础手感。

**与武器选择的一致性**：所有效果在 `playerAttack()` 里按 `currentUpgrades()` 读取，而 `upgradeKey()` 来自当前手持武器实例；配合 v1.8 的 `selected_weapon` 单一真值，玩家开局选刀、整局不会被剧情掉弓顶替，强化也就始终跟着「真的拿在手上的那把刀」走。换武器后状态互不带走，换回来还在。

## 4. 明确不迁

- 老游戏的「击杀攒经验 / 升级 / 每两关必得一次」节奏 —— 当前项目是波次节奏，改它会影响关卡结构与波次流程。
- `虎威之躯`（血量上限）、`疾行`（移速）等非攻击向卡 —— 本次只迁攻击向。
- `battle_talents.gd` 的知识锦囊跨局被动 —— 属于装备/成长系统，不在本次范围。
- 老游戏「选卡不暂停战斗」的 game2 做法 —— 当前项目统一冻结世界，保持一致。

## 5. 参数与验收入口

数值集中在 `game/public/data/config.json → wave_upgrade.melee`，类型在 `src/core/types.ts → WaveUpgradeTuning`。
纯逻辑与边界由 `tests/waveUpgrade.test.ts` / `tests/weaponSelection.test.ts` 锁定；浏览器实拍由 `tools/_cdp/weapon-selection.mjs`（全程不被换弓、九张卡、组合技）与 `tools/_cdp/wave-upgrade.mjs`（弓/近战/机枪互不影响、实例隔离）验证。
