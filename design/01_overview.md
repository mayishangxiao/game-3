# 第一章 设计总纲

## 1.1 一句话概念

> **你扮演历史中的人，亲手把每一件党史大事"做"一遍。**
> 一款手机浏览器即开的 16 位像素历史 RPG。玩家代入历史关键人物，亲历 1840—2026 年中国近现代史重大事件；剧情之外可进入副本打怪升级、刷装备，兼顾"学到知识"与"玩得下去"。

游戏的一句反命题是它的设计底线：**这不是一本会动的教科书，而是一台时光机。** 教科书告诉你"1927 年 8 月 1 日南昌起义打响了武装反抗国民党反动派的第一枪"；游戏让你在 8 月 1 日凌晨的城市街巷里，用手里的枪把这句话重新打响一次。

## 1.2 设计目标

游戏必须在三个方向上同时成立，缺一不可。三者冲突时的优先级为 **史实准确 > 玩得下去 > 内容量**。

| 目标 | 具体标准 | 衡量方式 |
| --- | --- | --- |
| **史实准确** | 时间、地点、人物、文件、结果五要素无错误；所有结论与党的历史决议口径一致 | 每个事件卡经 2 人交叉校对，附录 A 留存校对签名 |
| **玩得下去** | 首次进入 30 秒内开始操作；单关时长 3—8 分钟；教程关后不用看说明 | 同学试玩：能不看提示完成序章第一幕 |
| **知识可留存** | 通关一章后，能复述该章核心事件的时间与结果 | 章末测验 5 题，首次通过率 > 70% |
| **可持续** | 新增一章 = 新增 JSON + 贴美术素材，不改代码 | 第二章接入时核心代码零改动（允许新增非战斗模块脚本） |
| **可交付** | 第一期（序章 + 第一章）为一台可玩的完整产品 | 手机浏览器真机跑通全流程 |

## 1.3 四条体验支柱

所有玩法设计都必须服务于以下四条体验。任何一条说不通的关卡，回炉重做。

**支柱一：亲历感——"我在场"**
玩家不是旁观者。会议中他坐在桌边，战斗中他握着自己的武器，谈判中他必须开口。设计手法：第一人称视角的对话框、即时可动的地图、需要玩家手动完成的历史动作（举旗、投票、签字、升旗、发射）。

**支柱二：抉择感——"为什么这样选"**
党史的每一个转折点都是抉择：跟谁走、打哪里、谈不谈、改不改。设计手法：思想抉择模块 + 可选择但会回正的分支——**允许玩家选错，然后用后果教育他，而不是直接锁死流程**。历史上选错的路，游戏里也让玩家走一遍，再被历史纠正。

**支柱三：成长感——"我变强了"**
从关天培手里的一把刀，到新时代的一枚火箭。武器、装备、等级、技能随时间线推进而解锁，让"历史进程"变成玩家能摸到的数值成长。设计手法：武器按时代解锁表 + 五槽位装备 + 品质词条。

**支柱四：收获感——"我学到了"**
每次通关必须有可见的知识落袋。设计手法：每事件一张知识卡，进图鉴；图鉴收集给属性加成，让"学习"直接反哺"战斗"。

## 1.4 玩家旅程

| 阶段 | 时长 | 玩家在做什么 | 设计目标 |
| --- | --- | --- | --- |
| 首次接触 | 0—30 秒 | 打开链接 → 标题画面 → 点"开始" → 虎门海滩，跟随对话 | 无下载、无注册、秒开 |
| 第一小时 | 30—60 分钟 | 通关序章第一至第三幕，拿到第一件蓝色装备，收集 8 张知识卡 | 建立"历史 + 打怪"的双循环认知 |
| 第一次回流 | 次日 15 分钟 | 刷序章副本、补知识卡、挑战章末测验 | 用收集欲和对战欲驱动回流 |
| 单章周期 | 每章 40—70 分钟 | 剧情幕 → 战斗幕 → 章末测验 → 解锁下一章 | 一章一个完整的起承转合 |
| 全周期 | 三期合计约 12—18 小时 | 走完 1840—2026 | 通关即形成一条完整的个人党史时间线 |

**回流钩子设计（三条）**

1. **图鉴缺口**：每章有 2—3 张"隐藏知识卡"，藏在非主线的探索点或特定战斗评价里。
2. **装备词条**：紫色装备词条随机，刷副本永远可能有更好的那条。
3. **难度重打**：通关后解锁"史实考证"难度，敌人属性提升，但掉落品质提升，且通关给专属外观。

## 1.5 设计约束与内容红线

### 1.5.1 技术约束

| 约束 | 数值 | 影响 |
| --- | --- | --- |
| 首屏体积 | < 3 MB（目标 1—2 MB） | 图集必须压缩，音频用短样本，禁止大图预加载 |
| 内部分辨率 | 480 × 270（16:9），整数倍放大 | 战场区固定 30 × 16 瓦片 = 480 × 256，底部 14 px 归 HUD 条 |
| 瓦片尺寸 | 16 × 16 px | 单屏房间最多 30 × 16 格 |
| 角色尺寸 | 24 × 32 px 二头身，1 px 黑描边 | 四向各 4 帧行走 + 3 帧攻击 + 1 帧受击 |
| 运行环境 | 微信 / Safari / Chrome 内置浏览器 | 必须处理音频解锁手势、视口高度抖动、刘海遮挡 |
| 存储 | 浏览器 localStorage | 无后端、无账号；提供导出/导入存档字符串作为备份 |

### 1.5.2 人力与预算约束

单人开发，AI 辅助。唯一资源为阿里云 300 元百炼代金券（DeepSeek 档位模型）。因此：

- **代码骨架优先**：先把引擎跑通，美术用占位色块，最后贴图。绝不允许"等美术"。
- **内容全 JSON 化**：数据与逻辑分离，AI 生成的内容可以直接落入 JSON 而不碰代码。
- **复用旧资产**：旧 Godot 项目（鸦片战争／虎门／三元里等）中已完成的对话文案、章节结构、事件列表翻译为 JSON 直接复用。
- **单次 AI 调用产出可直接使用的内容**：对话文案按"每幕一次批量生成"组织提示词，减少往返轮数。

### 1.5.3 合规约束

- 不使用、不歪曲党和国家领导人形象；人物立绘与称呼严格遵循公开规范表述。
- 不使用未经授权的真实历史照片、纪录片截图、他人游戏素材。
- 音频、字体、图集全部使用免费可商用素材，并在文档第八章登记来源与许可证。
- 涉及现行政策、民族、宗教、领土的内容，一律只采用权威公开表述，不做演绎。

### 1.5.4 内容红线：敏感史实处理原则（R-05）

有些历史内容**必须讲，但不能玩**。规则如下：

| 类别 | 处理方式 | 示例 |
| --- | --- | --- |
| 侵略暴行、重大伤亡 | **不可玩化**：仅以静帧过场 + 文字 + 知识卡呈现，禁止战斗数值化、禁止"击杀数"、禁止娱乐化音效 | 南京大屠杀、抗震救灾伤亡 |
| 党内曲折与失误 | **结论化**：只呈现权威历史决议的结论，作为知识卡与剧情旁白，不设计任何可操作关卡 | 文化大革命等 |
| 已定论的历史人物 | **规范表述**：按公开权威表述使用姓名与职务称谓，不做戏说、不做网络化调侃 | 全部人物 |
| 牺牲与就义 | **庄重化**：使用克制镜头语言与静音处理，不用慢动作特效、不弹成就、不掉装备 | 关天培、谭嗣同、秋瑾、李大钊等 |

> **一句自检**："如果这段内容被思政课老师看到，他会认可这个呈现方式吗？" 答案不确定，就不做。

# 第二章 内容框架：从"历史事件"到"可玩节点"

本章回答时期框架表里那个悬而未决的问题——**"什么形式能实现关键词和事件的一一对应？"**——并给出可复用的判定方法。

## 2.1 三层内容结构

游戏内容由三层构成，越往下颗粒度越细、越容易替换：

```
时期框架表的一行（章）
   └── 幕（Act）            1 个章 = 3—7 幕
         └── 事件卡（Event）  1 个幕 = 2—6 张事件卡（= 表里的"核心事件"逐条拆分）
               └── 节点（Node）1 张事件卡 = 1—3 个玩法节点
```

**关键澄清**：时期框架表里"核心事件"栏的一串词，其实是**不同颗粒度的混合体**——"中共一大建立"是一个事件，"辽沈战役"是一个事件，"鸦片战争、太平天国运动"也是事件。要做成游戏，必须先**统一颗粒度**：把每个事件拆到"有明确时间、地点、主体、动作、结果"的最小单位。例如：

| 表里的写法 | 拆解后的事件卡 |
| --- | --- |
| 鸦片战争 | `ev_1839_humen` 虎门销烟（1839.6）· `ev_1840_war` 鸦片战争爆发（1840.6）· `ev_1841_humen_fort` 虎门炮台之战（1841.2）· `ev_1842_nanjing` 《南京条约》签订（1842.8） |
| 长征 | `ev_1934_breakout` 长征出发（1934.10）· `ev_1934_xiangjiang` 湘江战役（1934.11）· `ev_1935_zunyi` 遵义会议（1935.1）· `ev_1935_chishui` 四渡赤水（1935.1—3）· `ev_1935_luding` 飞夺泸定桥（1935.5）· `ev_1935_snow` 爬雪山过草地（1935.6—8）· `ev_1936_huining` 三大主力会师（1936.10） |

拆到这一层，"一一对应"才有落地的基础。

## 2.2 一事件一卡一节点原则（R-03）

> **每一个核心事件 = 一张事件卡 = 至少一个可玩节点 = 一张知识卡。**
> 不许有事件没有玩法（变成纯文字），也不许有玩法没有事件（变成无意义打怪）。

### 2.2.1 为什么这条原则能解决"一一对应"

原问题担心的其实是两件事：**表格里的关键词会不会在游戏里丢失？** 和 **游戏里的关卡会不会跑出党史之外？** 这条原则用双向锁死来回答：

**正向锁（关键词不丢）** —— 用第 2.5 节的"五要素校验"逐卡检查。一张事件卡必须同时具备时间、地点、人物、文件/口号、结果五个字段，缺任何一个就打回。这五要素在游戏中的落点位置是固定的：

| 要素 | 在游戏中的落点 | 玩家如何接触到 |
| --- | --- | --- |
| 时间 | 关卡载入标题条「1927.8.1 凌晨 · 南昌」 | 每关必看 |
| 地点 | 瓦片地图场景 + 载入标题条 | 每关必看 |
| 人物 | 化身 + 在场 NPC + 对话 | 每关必对话 |
| 文件/口号 | 道具化（会议文件、标语横幅、报刊），可拾取 | 探索必拾取 |
| 结果 | 关卡结束的"史实落点"卡（一页文字 + 一张知识卡） | 每关必看 |

**反向锁（玩法不跑偏）** —— 每个玩法节点的设计必须能回答："这个操作在历史里对应什么动作？"如果答不上来，说明这个玩法是为了好玩硬塞的，删掉。

> **示例**：给"遵义会议"做玩法，不能做成"打 Boss"。玩家在遵义会议里做的动作是——**把正确的意见投出来**。所以节点设计成会议还原型：听发言 → 判断哪条意见符合实际 → 投票 → 结果回放。操作上只是点选与投票，但历史动作完全对应。

### 2.2.2 一个事件卡的标准结构

| 字段 | 说明 | 是否必填 |
| --- | --- | --- |
| `id` | 事件卡 ID | 必填 |
| `title` | 事件名（权威表述） | 必填 |
| `date_text` | 时间（精确到年月，必要时到日） | 必填 |
| `place` | 地点 | 必填 |
| `figures` | 相关人物列表 | 必填 |
| `document` | 相关文件/口号/纲领（可为空但须显式说明） | 必填 |
| `result` | 历史结果（一到两句） | 必填 |
| `archetype` | 主玩法原型 A—J | 必填 |
| `nodes` | 玩法节点数组 | 必填（≥1） |
| `knowledge_card` | 知识卡 ID | 必填 |
| `hidden` | 是否为隐藏卡 | 选填 |

## 2.3 十大玩法原型（A—J）

全部章节的玩法都从以下十类中选取组合。**每一幕指定 1 个主原型 + 0—2 个辅原型**，避免玩法糊成一锅。

| 代号 | 原型 | 历史动作对应 | 玩法内核 | 操作方式 | 典型事件 |
| --- | --- | --- | --- | --- | --- |
| **A** | 会议还原 | 开会、发言、表决 | 座次对位 → 议程推进 → 意见表态 → 决议 | 点选、拖拽、投票 | 中共一大、遵义会议、十一届三中全会 |
| **B** | 谈判博弈 | 谈判、交涉、外交 | 多轮对话 → 筹码交换 → 底线试探 → 达成/破裂 | 选项、数值条 | 重庆谈判、恢复联合国席位、入世 |
| **C** | 即时战斗 | 作战、突围、伏击 | 摇杆移动 + 攻击/技能/闪避，波次与 Boss | 双摇杆/按键 | 虎门炮台、百团大战、淮海战役 |
| **D** | 沙盘推演 | 战略部署、战役指挥 | 资源投放 → 部队调动 → 时间轴推进 → 战果判定 | 拖拽棋子、时间轴 | 北伐、挺进大别山、三大战役 |
| **E** | 群众动员 | 罢工、游行、宣传 | 节奏连点 / 口号排序 / 横幅拼字 / 人群汇聚 | 点击节奏、顺序排列 | 五四游行、五卅运动、一二·九 |
| **F** | 探索收集 | 考察、调研、走访 | 瓦片地图走动 + 交互点 + 收集物 + 隐藏点 | 摇杆移动、靠近交互 | 江南制造局、北大红楼、南泥湾 |
| **G** | 建设经营 | 生产、建设、经济恢复 | 资源分配 → 生产链 → 时间推进 → 指标达成 | 分配滑块、建造 | 井冈山根据地、一五计划、脱贫攻坚 |
| **H** | 科研解谜 | 技术攻关、科学实验 | 机关拼合 / 参数调试 / 工序排序 | 拖拽、调参、排序 | 两弹一星、航天发射 |
| **I** | 思想抉择 | 论战、路线选择、立场 | 对话树分支 → 立场值 → 后果回放 | 选项 | 公车上书、真理标准讨论、农村改革 |
| **J** | 展示过场 | 就义、宣言、胜利、悼念 | 剧情演绎 + 知识卡落点 | 点击推进 | 谭嗣同就义、开国大典、抗战胜利 |

### 2.3.1 原型配比规则

- **战斗（C）占比不超过全内容的 40%**。这是历史知识游戏，不是割草游戏。
- 每一幕结束后必须有一个非战斗的"静场"节点（J 或 A 或 I），用于沉淀知识。
- 连续两幕不得使用同一主原型。
- 序章以 F/I/E 为主（因为这一时期"没有胜利的仗可打"），第二期以 C/D 为主，第三期以 G/H/B 为主。**玩法配比本身就是历史叙事的一部分。**

### 2.3.2 通用插片 Q（知识问答）

除十个原型外，还有一类**不占原型名额的通用插片**：**Q · 知识问答**。它可以插进任何一幕的任何节点之后，形式为 1—3 道选择题，用于当场确认玩家是否记住了刚刚经历的事件。

- Q 不算"幕的主玩法"，只用于调节节奏与即时反馈。
- 每幕最多插 1 次，避免游戏变成做题。
- Q 与章末测验共用一个题库，但 Q 只抽本幕相关的题目。
- 示例：序章第一幕"虎门销烟"之后插 1 题"虎门销烟发生在哪一年"——既让玩家认识 Q 的形态，也当场巩固知识。

## 2.4 事件到原型的判定四步法

设计任何一张新事件卡时，按以下四步走，10 分钟内可定案。

1. **问"历史现场的人在干什么？"** —— 写出这个事件中，当事人最主要的一个动作（一个动词）。
2. **把动词映射到原型** —— 查下表。
3. **检查可行性** —— 是否有地图/敌人/数值支撑？若第一期做不了（如需要复杂 AI 的沙盘），先降级为 J + 知识卡，标记为"待二期升级"。
4. **写"动作对应说明"** —— 一句话写清"玩家做的操作 = 历史里的什么动作"。写不出来就回到第 1 步。

| 现场动词 | 原型 | 现场动词 | 原型 |
| --- | --- | --- | --- |
| 开会、表决、决议 | A | 生产、建设、分配 | G |
| 谈、交涉、争取 | B | 攻关、试验、计算 | H |
| 打、守、突围、伏击 | C | 争辩、选择、站队 | I |
| 部署、调动、指挥 | D | 就义、宣告、庆祝、悼念 | J |
| 罢工、游行、宣传、发动 | E | 走访、考察、收集 | F |

## 2.5 关键词五要素校验（验收工具）

每张事件卡做完后，用下表逐行打勾。这是**史实风险的主要防线**，也是章节交付的验收项。

| 校验项 | 通过标准 | 反例（不通过） |
| --- | --- | --- |
| 时间 | 精确到年月；重要事件到日；与权威表述一致 | 只写"1927 年"而事件实际是 8 月 1 日 |
| 地点 | 具体到城市/建筑；地名用当时名称并注明今名 | 只写"南方某地" |
| 人物 | 姓名与职务表述规范；不虚构历史人物发言 | 让历史人物说不符合其立场的话 |
| 文件 | 有文件/纲领/口号的必须带出全称与要点 | 提到"一个决议"却不说是什么决议 |
| 结果 | 一到两句，与党的历史结论一致 | 只写"最后胜利了" |
