# src/ —— 代码地图

> 这份文件写给「接手改这个工程的人或 AI」：**先看这里，再决定打开哪个文件**。
> 每个条目包含：职责 / 主要导出 / 改它会波及谁。改完代码请同步这里，`tests/docs.test.ts` 会检查文件与本表是否一一对应。
>
> 重新生成骨架骨架用：`node tools/map_repo.mjs .`（打印每个文件的头部注释 + 导出符号）。

## 分层与依赖方向

```
main.ts
  └─ scenes/            ← 全部玩法都在场景里，场景之间靠 EventBus 通信
       ├─ systems/      ← 输入、对话框（被 UIScene / LevelScene 调用）
       ├─ entities/     ← 玩家、敌人（被 LevelScene 创建与驱动）
       ├─ gfx/          ← 占位矢量美术、瓦片渲染
       └─ core/         ← 数据、数值、存档、纯玩法逻辑
```

**硬性约束：`core/` 里的 20 个模块（balance / cannon / constants / critShake / DataLoader / defeat / dungeon / escort / EventBus / graph / management / orientation / quiz / SaveManager / space / types / upgradeSelection / waveUpgrade / weaponSelection / weaponSwap）不 import Phaser。**
这条线是单元测试能跑在 node 环境的前提（`vitest.config.ts` 里 `environment: 'node'`）。往这些文件里加 `import Phaser` 会让 20 个测试文件全部炸掉。
需要渲染的东西一律往 `scenes/` 或 `gfx/` 放。

## 已知陷阱（都是真踩过的）

1. **别用 Phaser.Scene 的内置成员名做字段**：`events` / `scene` / `input` / `time` / `cameras` / `add` / `children`。`GraphScene` 曾用 `private events` 直接 `TS2416`。
2. **`this.scene.start()` 会停掉自己，`game.scene.start()` 不会。** E2E 脚本里用后者曾导致两个场景叠在一起渲染（截图字节完全相同）。
3. **`transitioning` + `nodeBusy` 双闸门**：节点切换中会 `await buildWorld()`，若提前放开 `nodeBusy`，异步回来的 `startNodeInner` 会把整个节点跳过（曾导致经营节点被整段忽略）。
4. **掉落先进地面**：`rollDrop` 把装备丢到 `floorItems`，玩家走过去（`collectNearbyItems`）才进 `runDrops`。所以「这趟没掉东西」不能只看 `runDrops`——`finishDungeon` 会把剩余地面物品一起收走。
5. **硬阴影只能从调色板取色**：用 `darkerOf` / `lighterOf`，不要写数字 tint 运算，否则破坏 24 色纪律。
6. **`Enemy.takeDamage` 不触发死亡回调**（见上表）。
7. **Phaser 3.90 不会自动调用场景里名叫 `shutdown` 的方法。** dist 里 `Systems.shutdown()` 只做 `events.emit(Events.SHUTDOWN, this, data)`，全文没有 `scene.shutdown` 这段接线。`HubScene` 原来就指着隐式钩子收 DOM，第二次离开长廊时副本面板/底部四入口全留在原地压住战斗画面（甲方手机截图「有文字重叠」的第一处）。规矩：**谁往 `#dom-ui` 塞东西，谁就在 `create()` 里 `this.events.once(Phaser.Scenes.Events.SHUTDOWN, ...)` 自己收**（create 每次进入都重跑，用 `once` 不会越积越多）。`LevelScene.boot()`  additionally 在第一个 `await` 之前先 `hideOverlay/hideDialogue/hideFloat`——手机上章节数据要下几百毫秒，这期间战役条已经画出来了，不收就会叠。
8. **文字搬到 DOM 后，canvas 那份隐藏 Text 不能再被 `setHudShown(true)` 点亮。** `UIScene` 右上角「暂停」曾同时存在 canvas 版（`setVisible(false)` 藏着）和 DOM 版，而 `setHudShown()` 的 parts 列表把 canvas 版一起 `setVisible(v)`，于是每次恢复 HUD 就出现「暂停暂停」两个词。canvas 版已整个删掉；以后搬文字就删干净，别留一个「隐藏但会被点亮」的对象。
9. **`hideOverlay()` 的「删掉 #dom-ui 下所有不在白名单里的 div」会误伤常驻 HUD。** 右上角「暂停 / 背包」两行字也直接挂在 `#dom-ui` 下，早年白名单只列 `#dom-title` … `#dom-float`，于是开场情境卡关闭、关暂停、换节点的每一次 `hideOverlay()` 都把它们 remove 掉，canvas 上两块底板却还在 → 甲方截图「右上角两个框里没有字」。现在常驻节点统一打 `data-dom-ui-persist`，`UIScene.syncTopButtons()` 每次同步还会幂等补齐（被外部删了也长回来），`SHUTDOWN` 时由 UIScene 自己收。**以后往 `#dom-ui` 直接塞常驻节点，记得打这个标记并自己挂 SHUTDOWN 清理；临时节点别打，否则会留在下一屏。**
10. **DOM 文字层用固定 px 定位前先想清楚它挂在哪个坐标系。** 两枚按钮文字原本用 `right:14px` / `right:54px` 直接挂在宽度 = 画布 CSS 宽度的 `#dom-ui` 上，画布一放大（960px 宽 → 逻辑坐标 ×2），两行字就一起挤进右边那块底板、左边空着。修法是套一层固定 480×270 的逻辑坐标盒再整体 `scale(s)`（和 `#dom-overlay` 一样），而不是逐个改 right/top/字号——后者在 s=1 时看着对，换个屏又错。

## 本轮新增的不变式（甲方七条反馈带出来的）
- **暂停必须真冻结**：`UIScene.openPause()` 走 `this.scene.pause("Level")`（排队的场景操作，`isPaused()` 要等一帧才变），同时 `setControlsVisible(false)` 与 `setHudShown(false)`；`closePause()` 只恢复暂停前露着的那些。别用「update 里加个 if」代替场景暂停——补间、计时器、敌人计时都会继续跑。
- **目标文字跟着战役条**：`objectiveText.y` 在 `onSceneLabel()` 里按 `scenePlate.y + scenePlate.height + 3` 重算，没有战役条时回到 38。改战役条高度或行数要连带看这一行。


- **可交互物不能落在虚拟按键的命中区下面**。`CONTROL_LAYOUT` 是权威来源，`LevelScene.spawnWorldObject()`
  会把物体往安全位置推（见 `constants.CONTROL_LAYOUT` + `tests/data.test.ts` 的「箱子不在按键区」断言）。
- **海水是碰撞格**：`MapRenderer.extraSolid` 回调在 `isSolidAtWorld()` 里最先问，敌人与掉落都要用
  `LevelScene.landingNear()` 落回岸上，否则玩家打不到也捡不到。
- **`nearestOpenPoint` 的 `blocked` 收的是像素坐标，不是瓦片索引**。`LevelScene.landingNear()` 原来把形参
  命名成 `gx/gy` 又当列号用，像素值 376 被当成列号 → 越界 → 一律返回 true → 环形搜索永远返回 null →
  退化回原坐标。后果是**击退把敌人推出地图后没有任何落点可回去**（甲方三次截图报「小兵被打出地图」）。
  `tests/space.test.ts` 现在有一条用例直接跑「起点在地图外」并断言 `blocked` 收到的是格心像素。
- **击退要查落点**：`CharacterRig.knockback(dx, dy, unsafe?)` 是 tween 直接平移、不经过地形，
  调用方（`LevelScene.damageEnemy`）必须传 `enemySpotUnsafe`，它内部会对不可站的落点做二分收缩。
  另外 `LevelScene.rescueStrayEnemies()` 每帧兜底，把「地图外 / 军舰压出的海面 / 原始海面 / 墙里」
  的敌人拉回最近空地——判据统一在 `enemySpotUnsafe()`，别在别处另写一套，两处漂移过一次。
- **剧情闸门写在数据里**：`node.params.npc_talk = { npc, dialogue }` 决定「先说谁的台词、什么时候放开箱子」，
  代码里不留 if-else 拼章节。
- **本帧按下标志只能由 `LevelScene.update()` 末尾的 `controls.endFrame()` 清**（UIScene 里清会吞掉单点）。
5. **剧情闸门写在数据里**：`params.npc_talk = {npc, dialogue}` 会在 NPC 头顶挂感叹号并挡住 `pickup`，`npcTalked` 由 `finishNpcTalk()` 置真；`params.crate_target = 0` 表示这一幕不搬箱（箱子全部收起、出口一开始就开、目标改读 `params.objective`）。两者都只读 node 的 params，不认地图。
