# 党史像素 RPG（游戏工程）

手机浏览器即开的 16 位像素历史 RPG。玩家代入历史关键人物，亲历 1840—2026 年中国近现代史重大事件。

技术栈：**Phaser 3.90 + TypeScript 5.9 + Vite 8**，纯前端、无后端、全 JSON 驱动。

设计依据：《党史像素 RPG 游戏·完整设计书 v2.0》（见上级目录）。本工程按设计书 **第九章 9.1 的 WBS** 开发。

## 快速开始

```bash
cd game
pnpm install        # 首次
pnpm dev            # 开发服务器
pnpm build          # 类型检查 + 生产构建（产物在 dist/）
pnpm test           # 单元测试
```

本机若没有全局 Node，可用 DSH 运行时自带的 Node：

```powershell
$node = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
$pnpm = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\pnpm\bin\pnpm.mjs"
& $node $pnpm run build
```

操作：`WASD / 方向键` 移动，`J / 空格` 攻击，`K` 或「技」键重击（1.5 s 冷却、伤害 ×1.9、带冲击波），`L / Shift` 或「闪」键闪避，`E` 交互，`Esc` 暂停。攻击与重击**自动朝向最近的敌人**（近战 刀锋+34 px、远程 160 px 内），不用先转身对准。

左上角常驻一条「战役条」：`清王朝 血量` / `幕名 · 这一场　年份`（例如「鸦片战争 · 虎门炮台守卫战　1841 年」）。战役名与年份来自 `public/data/nodes/*.json` 的 `title` / `year`，**改数据就能改显示，不用改代码**。
经营模块：`↑↓` 换项目，`←→` 加减点数，`Enter` 确认。测验：`A/B/C/D` 作答，`Enter` 下一题。
装备界面：`←→↑↓` 选格，`E / Enter` 装备，`X` 拆解，`R` 强化，`Esc` 返回（触屏直接点格子选中、再点底部按钮）。
图谱：点两个节点连线，再点同一个节点可取消选择，`Esc` 返回。
手机端为左下虚拟摇杆 + 右下三键，横屏游玩。

标题页有「导出存档 / 导入存档」：导出的是一串可粘贴的文本（Base64），换域名、换设备、清缓存之后都能搬回去。手机上没有控制台，这是唯一的救存档手段——**换隧道地址就是换 localStorage，进度会「消失」**。

手机端进入方式（老掌机那一套）：打开页面先看到一整屏的「点击屏幕开始」，**点一下就横屏**。点之前引导层保持正立（竖着能读），点下去之后：

1. 这一下点本身就是手势，立刻申请全屏 + `screen.orientation.lock('landscape')`；能锁上就交给系统转；
2. 锁不上（iOS Safari 不支持 `lock`）就整屏 CSS 旋转 90°，靠 `#game-root` 的宽高互换铺满，同时把 Phaser 的父容器尺寸、`autoCenter` 与指针变换一起改掉，保证**触摸点仍然落在它看起来落在的位置**；
3. 用户真的把手机横过来之后，`orientationchange` 会把 CSS 旋转撤掉，恢复原生横屏渲染。

竖屏时引导层上并排两个按钮：左边「点 击 屏 幕 开 始」（进游戏），右边「⟳ 横屏」（只把画面转横、**不算开始**，方便先试试横过来的样子）。**引导层本身不参与 CSS 旋转**：`html.rot` 下它只保持 `inset:0` 铺满视口，所以无论转没转，文字都是正的、两个按钮都左右并排，玩家不用歪头看。曾经让 gate 跟着转、再靠 `.tg-in` 反向转回来，正负 90° 全试遍都调不对（不是跑出屏幕就是上下颠倒），这条路别走回头。另见 [src/README.md](src/README.md) 里 `systems/OrientationGate.ts` 那一行的注意事项。

竖屏时右上角还有一个「⟳ 横屏」小按钮（`#rotate-btn`）：旋转被撤掉后还想横着玩，点它就能再强制横一次（它同样能重新申请全屏与锁屏，因为这也是一次新手势）。按钮会跟着画面一起旋转，所以转好之后它就贴在用户眼里的右上角。

不想要自动转屏的话，地址后加 `?norot=1`：竖屏只弹「请把手机横过来」的整屏提示，画面绝不自己拧起来，也不显示那个按钮；`?rot=1` 则强制走 CSS 旋转（调试坐标反算用）。

细节与坐标反算的推导在 [src/README.md](src/README.md) 的 `core/orientation.ts` / `systems/OrientationGate.ts` 两行；端到端判据在 [tools/README.md](tools/README.md) 末尾。

### 首屏为什么这么拆（弱网/隧道下最要紧的一条）

引擎 `phaser.min.js` 有 1.17 MB，**不打进应用 bundle**：`src/main.ts` 先 `loadPhaser()`（360 CDN → unpkg → bootcdn → 同目录 `./phaser.min.js` 兜底，单源 9 s 超时），成功后才动态 `import('./boot')`。

- 不这么做的后果（实测）：整包 1.3 MB 经隧道到手机要 **70 秒**，那段时间页面停在「点击屏幕开始」，游戏脚本还没到 —— 用户看到的就是**点哪都没反应**，而且没有任何加载提示。
- 现在：应用自身 105 KB（gzip 33 KB），首屏必须下载 248 KB（含 22 个数据 JSON，`data/` 约 134 KB），引擎走 CDN。本机实测「导航 → 可交互」**约 1.1 s**。
- 引导层有「先手」监听：主模块还没到时先点，会立刻显示「载入中…」；就绪后改成「再点一下进入」（全屏与方向锁只认新手势）。
- 排障开关：地址后加 `?dbg=1` 会在左上角显示 UA / 视口 / `__dshGate` 状态 / 每个触点的屏幕坐标→游戏坐标；加 `?norot=1` 关闭 CSS 旋转兜底（只提示用户自己横过来）。

### 可重复内容（长廊底部四个入口）

- **副本**：长廊左上角列出 3 个副本，通关对应幕解锁。`租界暗巷`（第 1 幕后，Lv3）、`广州城外匪寨`（第 2 幕后，Lv5，Boss 匪寨首领）、`沪上码头`（第 2 幕后，Lv6）。每趟 3—4 波 + Boss，掉白/蓝/紫装；**首通必掉一件该副本专属装备**，之后再刷只按权重掉落。连续 5 趟没出紫装，第 6 趟起紫色权重 +25（从白色权重里扣），出紫即清零。
- **装备**：五槽位（武器/头/身/腿/饰品）+ 12 件一页的背包。点格子选中（触屏同样可用），底部四个键：装备 / 卸下 `E`、拆解 `X`（换零件）、强化 `R`（每级 +8% 主属性，最高 +5，消耗零件递增）、返回 `Esc`。已装备的那件可以选中强化，但必须先卸下才能拆解；左下角显示选中装备的基础值、强化后数值与随机词条。
- **图谱**：把事件卡按「一件事导致了下一件事」连起来，共 15 条必需边；只有亲历过的事件节点才能连线，连错给提示。全部连通解锁成就 `graph_complete_ch00`，连线结果存档。

| `dungeon.test.ts` | 27 | 保底阈值 5 的边界、权重守恒（只从白色扣、不为负）、`isPityReady`、通关计数与落盘、按幕解锁、首通才给专属装备 |
| `graph.test.ts` | 34 | 边键对称/去重、自指与悬空边被丢弃、非法连线的五种返回值、**空图不算完成**、连通分量，以及真实数据无自指无孤岛 |
| `data.test.ts` | 35 | 引用完整性（节点/事件/知识卡/敌人/对话/地图/副本/装备）、Boss 阶段区间、对话字数、**地图可达性 BFS**、副本权重和为 100、副本地图有右侧敌人出生点 |
| `docs.test.ts` | 11 | **文档对齐**：每个源文件/数据文件/测试/脚本都写在对应目录的 README 里，README 的相对链接都能解析 |

其中三条是「设计意图」而非「实现细节」的锁：

- **经营模块无论怎么分都会崩**：穷举全部 19 种合法分配（三项和为 6、单项 ≤ 4）逐月固定执行的策略，无一能守住。这是设计书 3.3.2「农民阶级的局限性」的机制表达，不能被后续平衡调整悄悄破坏。
- **地图可达性**：BFS 验证每张地图的出生点能走到所有可交互物（本身或四邻），护送地图的**右端必须可达**，战斗与副本地图**右侧必须有敌人出生点**。这类内容 bug 在真机试玩前极难发现，但会让关卡直接不可通关。
- **保底只从白色扣、图谱空图不算通关**：保底是「把 25 点权重从白色挪到紫色」，总权重必须守恒且不为负——否则改一个数字就能让紫装必掉；图谱完成度 `0/0` 也不能算 100%，否则一张没有事件卡的章节会白送成就。

### 情境化战斗（瓦片材质 / 开场情境卡 / 水坑脱困，2026-07）

甲方（老师）的要求：「背景上写上时间、地点、对方出兵数量，背景是海面斗争」「技术上不用那么复杂，核心是知识点——简单斗争一下就行」。落成三件事：

- **开场情境卡**（`LevelScene.showBattleIntro`）：全屏海战背景 + 大字时间（1841 年 2 月）+ 地点（虎门 · 威远炮台）+ 双方兵力（我方广东水师 · 虎门六炮台 / 敌军英舰 10 余艘 · 陆军 2000 余人），点一下开打。卡片开着时**世界冻结**、HUD 与操控整块收起。数据在节点上：`nodes_ch00.json → banner: {time, place, ours, enemy, scene}`，加一场只要加这条数据，不用改代码（`tests/data.test.ts` 会检查 time 必须含年月、place/enemy 不能空）。
- **瓦片不再是一格一格纯色砖**：`MapRenderer` 把地面整层烘成一张 canvas 纹理，按颜色推材质——海面画浪脊与浪花、沙地画砂点、石墙画砖缝、木栈道画木纹。判「海」的阈值改成**蓝得明显**才认（b−r ≥ 60 且 b−g ≥ 20）：第一版 `b > r + 20` 把紫灰的炮台地面 `#6B6489` 也当成了海，整片场地被画上浪花，截图里看着像站在水上。
- **战斗场景自带远景背景**（用户要求「我想要战斗的时候也有背景」）：只做开场卡不够，打起来还是俯视格子地。做法是地图数据加 `sky_rows`（`map_ch00_act1b` 为 3），那几行本来就是实心墙、玩家站不上去，`MapRenderer` 就不画地砖，`LevelScene.buildWorld` 在那条透明带上叠 `Backdrop.horizonTexture()`——天空色带、低日、海平线、三艘敌舰剪影、波光。实体仍渲染在远景之上，所以舰船从上面压过来时是「从海平线驶近」的观感。换成正式美术只要替换那一个 `*Texture()` 函数。
- **水坑卡死修掉了**：军舰前压会把碾过的地面画成海，而海面是运行时禁区、不在碰撞数据里，旧版脱困逻辑只查地图碰撞，于是永远判定「你没卡住」。现在 `ejectPlayerFromSea()` 用 `core/space.ts` 的 `nearestOpenPoint` 按圈向外找最近的可站点（同时排除海面与墙），并且**每帧兜底**，玩家一旦踩进水里就被挪回岸边并提示「水太深了，退回岸上」。

验证：`tools/_cdp/scene.mjs` 探针在此之前先抓到一个渲染崩溃（`Cannot read properties of null (reading 'glTexture')`）——`MapRenderer` 用固定 key 重建地面纹理，上一帧还在渲染的 Image 拿到已删除的纹理。改成每实例唯一 key + `destroy()` 里回收，现在探针 `errors: []`，三张截图（卡片 / 战场 / 脱困后）已逐张看过。

## 开发过程中发现并修正的问题

### 代码 bug（会被玩家直接遇到）

| 问题 | 现象 | 修复 |
| --- | --- | --- |
| **闪现进入军舰压出的水坑后走不出来**（本轮，玩家 m05665 实测） | 军舰前压会把地面变成海面，但海面**不是碰撞格**（`isSolidAtWorld` 永远返回 false）；脱困函数只 `while (isSolidAtWorld) x -= 6`，一次都没生效过 → 角色站在水里动不了，看起来像卡死 | `core/space.ts` 的 `nearestOpenPoint()` 按圈向外找最近可站点，`ejectPlayerFromSea()` 的「不可站」判定同时查 `isSeaAt`（运行时禁区）与 `isSolidAtWorld`，并在 `updateWorld()` 每帧兜底，附 toast「水太深了，退回岸上」 |
| **重进关卡后波次永远不推进**（本轮，美术接入时抓到） | `scene.start('Level')` 复用同一个实例，`create()` 不清 `transitioning`；若上一轮在切节点的 `await` 里被重开，这个标志一直是 `true`，`updateWorld()` 开头就 `return` → 清完第一波后**永远等不到 Boss**（表里看着一切正常：`mode: combat`、`wavePending: false`、敌人 0 个） | `create()` 的重置段补 `this.transitioning = false; this.pendingCardTap = null;`，并在注释里写明「updateWorld 开头就是这一句」 |
| **副本结算面板被虚拟按键压住**（本轮） | UIScene 渲染在 LevelScene 之上，`setDepth` 跨场景无效；摇杆和三个键正好盖住结算面板的下半部分，手机上点不到「再刷一次」 | 新增 `EV.CONTROLS_VISIBLE` 事件 + `InputSystem.setShown()`（视觉件与命中区一起隐藏），结算期间隐藏操控层、再刷/返回时恢复 |
| **知识图谱出现自指边与孤岛**（本轮） | 单测跑真实数据时炸出两个真 bug：`kc_1859_zizheng` 的 `links` 里包含自己；ch00 的 11 个事件断成两段互不相连 | 自指换成「《天朝田亩制度》→ 天京陷落」；补 `kc_1842_nanjing` → `ev_1851_jintian`（条约冲击催生起义）把两段接成一条线，并写成断言防止回退 |
| **副本一趟掉两件同模板**（本轮） | 同一趟里可能连续掉两把「匪寨大刀」，读起来像程序出错 | `rollDrop` 先用本趟已掉的 `base_id` 过滤候选池，空了才回退全池 |
| **图谱连线读不出因果**（本轮） | 网格排布让相邻节点可能隔着一整行，斜线穿满屏幕 | 改成按年份蛇形排布；跨 3 个以上时间序号的边画虚线并压暗，主线用实线浮出来 |
| **长廊副本面板糊成一团**（本轮） | 标题与第一条目重叠，且没有底板，白字直接压在长廊地板上 | 面板改为先量条目数再画底板，标题与条目分开 4px |

### 测试自身的修正（也是收获）

| 问题 | 说明 |
| --- | --- |
| **`GraphScene` 里不能用 `events` 当字段名**（本轮） | `Phaser.Scene` 自己就有 `events`（事件发射器），覆盖它会 `TS2416`；改名 `cards` 才对。同理不能占用 `scene` / `input` / `time` / `cameras` |

| PowerShell 写 JSON 会加 BOM（本轮） | `Set-Content -Encoding UTF8` 写入 BOM，`JSON.parse` 直接 `Unexpected token ''`。改为按 `utf-8-sig` 读、以无 BOM 字节写，并全量检查 `public/data` |

| 验证脚本没关对话（上轮） | 炮台节点的开场对话还开着就去观察 Boss，而 `update()` 在对话期间会 `return`（对话暂停战斗，是刻意设计）→ 得出「Boss 一次招式都不放」的**错误结论**。加探针测出 `calls: 0` 才定位到真因是脚本而非代码 |

### 战败演出（城破）

虎门这一战史实上就是输的，所以玩家血条清零后不再「重打一次」，而是走一段演出：

1. **定格留白**：世界冻结、HUD 与虚拟按键收起、战斗音效静音，黑边从画面外滑进来（约 0.4 秒什么都不发生）。
2. **镜头拉远**：战场摄像机缩到 0.7 倍并压暗，读作「退到江面上看这场败仗」。
3. **江面与舰队**：海战背景淡入并缓慢推近，炮火余响先响。
4. **城破**：一声闷响之后大字才出现（`虎门城破` 从小到大 + 轻微抖动），再出副行与落款。
5. **收尾**：全部淡出、镜头复位、HUD 复位，接《南京条约》卡片 → 清王朝血条下跌 → 关天培殉国 → 继续推进。

节奏全部写在 `src/core/defeat.ts` 的 `DEFEAT_BEATS` 里，由 `tests/defeat.test.ts` 守住两条硬要求：
留白必须在最前且 ≥300ms、大字不得早于音效（甲方原话「不要直接弹出文字」）。
演出层单独开一台摄像机（`DefeatCinematic`），否则战场摄像机拉远会把黑边和背景图一起缩小。

文案按关卡写在节点数据里：`params.breach_title / breach_line / breach_note`，缺省用 `DEFEAT_TEXT` 兜底。
