# tests/ —— 测试地图

> 测试在这个项目里不是「覆盖率作业」，而是**把设计意图钉住的钉子**。凡是「看起来像 bug、其实是有意为之」的地方，都有一条测试写着原因，防止后来的人（包括我自己）把它「修」掉。
>
> 现状：**35 个文件 / 604 条测试**，全在 node 环境跑（不 import Phaser），`pnpm test` 3 秒内跑完。

## 怎么跑

```bash
pnpm test            # 一次跑完（vitest run）
pnpm exec vitest     # 监听模式
pnpm exec vitest run tests/dungeon.test.ts   # 只跑一个文件
```

- 配置在 `vitest.config.ts`：`include: tests/**/*.test.ts`，`environment: 'node'`。
- 因此**测试里不能 import Phaser**：被测模块必须是 `src/core/` 下那 23 个不依赖 Phaser 的文件（见 `src/README.md` 的硬性约束）。要测场景/渲染就得靠 `tools/cdp-*.mjs` 的真实浏览器端到端。
- 读数据文件用 `process.cwd()` 拼路径（不是 `__dirname`），因为 vitest 以工程根为 cwd。
- 解析 JSON 记得拆包装层（`{events:[]}` / `{cards:[]}` / `{dungeons:[]}`…），详见 `public/data/README.md`。

## 写新测试的约定

1. **能被纯函数表达的规则，就别留给端到端。** 数值、掉落、保底、图谱、经营这类「算出来对不对」的东西一律进 `tests/`；「面板有没有弹出来、按钮点得动吗」才交给 CDP。
2. **断言要写清「为什么」**，尤其是反直觉的：
   ```ts
   // 这是设计意图（农民阶级的局限性），不是平衡 bug —— 别把它「修」成能守住
   expect(result.won).toBe(false);
   ```
3. **否定式断言要防 0/0**：图谱进度、完成度这类比例值，空集合必须是「未完成 / 0」而不是 NaN 或 100。
4. **数据测试读真实文件**，不要复制一份 fixture——复制的那份永远和线上数据不一致，测了个假的。
5. 新增 `src/core/` 模块就顺手加一个 `tests/xxx.test.ts`；新增目录就顺手更新本文件的表格。
